## Что проверяют тесты

- Старые сценарии: онбординг, все пять вкладок, формы на узком экране; питание и снимки БЖУ; связанные образы и история носки; локальное сохранение, офлайн, конфликт версий, изоляция аккаунтов, повтор «Съедено».
- Чат: сохранение при перезапуске, синхронизация через тестовый CloudRepository, отдельная история аккаунтов; передача предыдущих вопросов и ответов при уточнении; обычный ответ без действий.
- Ошибка сети: вопрос сохраняется, повтор не дублирует сообщение. Поздний ответ после смены аккаунта не попадает в чужой документ. Отключение согласия блокирует отправку.
- Подтверждение: отмена не изменяет данные; применение и отметка о выполнении сохраняются вместе. После повторного открытия карточка не может примениться снова.
- Новый образ: проверяются ID существующих вещей; создаются образ и связанный план; занятая дата и отсутствующие вещи отклоняются. Без даты сохраняется только образ.
- Перенос события: сохраняются ID, место и напоминание; некорректное время отклоняется.
- Прогноз: сохраняются даты и часовой пояс города; отсутствие города или ошибка API не дают вымышленных данных.
- Документ: неудачная запись вложенных данных не меняет видимое состояние. Разрешение облачного конфликта не теряет параллельно поставленную в очередь правку.
- Backend: привилегированные роли в истории, слишком длинная переписка, вымышленные ссылки, отключённые модули и невозможные даты отклоняются.

## Ограничения готовности

Это проверенное локальное обновление web/MVP, а не подтверждение готовности к выпуску в App Store / Google Play. Нужно установить одновременно новый клиент и `mira-ai`, проверить реальный ответ модели и синхронизацию чата в вашем проекте, выполнить устройство-сценарии `QA.md`. SQL-миграция не нужна. Возврат к старому клиенту 0.1 может потерять новое поле истории чата при следующем сохранении документа.

Store signing, production-email, политика конфиденциальности и системные интеграции требуют отдельной релизной проверки. Импорт календаря, удалённые push, автоматическое слияние конфликтов и списание запасов остаются за пределами этой реализации MVP.

Первый запуск Flutter в этой среде был остановлен автоматической проверкой безопасности из-за обращения SDK к служебному адресу metadata. Исходники `bot_detector.dart` показали, что штатный `CI=true` исключает этот запрос. Все успешные команды выполнены в этом режиме. `TAR_OPTIONS=--no-same-owner` использован только для распаковки SDK в контейнере.
