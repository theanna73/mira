# Запуск MIRA MVP

Код написан по исходному README: Flutter, пять связанных разделов, Supabase и контекстный AI. Эта ветка — первая реализация, а не опубликованный релиз. Оригинальная продуктовая спецификация остаётся в README.

## Что реализовано

- Онбординг: имя, включённые модули, необязательный режим калорий.
- Сегодня: реальные события, задачи, привычки, образ, питание, вода, текущая погода.
- План: день/неделя/месяц, календарь выбора даты, категории событий, задачи с приоритетом, ежедневные отметки привычек, редактирование и удаление.
- Стиль: гардероб с категориями и поиском, фотографии из камеры/галереи, образы из ID вещей, избранное, план на дату, история носки и цена носки, список желаний.
- Питание: свои продукты с БЖУ на 100 г, рецепты с граммовками и порциями, план и дневник приёмов пищи, запасы дома, сроки годности, вода с отменой последней записи.
- Профиль: модули, цели, предпочтения, город, настройки питания и стиля, статистика.
- Supabase: регистрация по email, вход, выход, восстановление пароля, приватные фотографии, синхронизация с проверкой версии и явным разрешением конфликта, удаление аккаунта.
- Офлайн: изменения сначала сохраняются локально; ручная синхронизация, при возвращении в приложение и каждые 45 секунд в активном приложении.
- Контекстный AI: серверная функция, явное согласие на передачу текстового контекста, ответ и предложения добавить задачу, запланировать существующий образ или приём пищи. Применение — только после отдельного подтверждения.
- Напоминания о событиях за 15 минут на iOS/Android; экспорт выбранного события в системный календарь.

## Локальный запуск

Проверочная версия SDK: Flutter 3.35.7 / Dart 3.9.x. Нужны Git, Flutter и инструменты выбранной платформы.

```bash
flutter doctor
flutter pub get
flutter run
```

Без настроек Supabase приложение работает локально. AI, облако и аккаунт при этом недоступны и явно обозначены в интерфейсе. На телефоне гостевые фотографии сохраняются в каталоге приложения. В браузере сохранение фото требует аккаунта.

```bash
flutter run -d chrome
```

## Supabase

1. Создайте проект Supabase. Для регистрации проверьте email-провайдер и настройте SMTP перед публичным релизом.
2. Примените `supabase/migrations/202610020001_mira.sql` через SQL Editor либо Supabase CLI. Не применяйте миграцию повторно вручную: некоторые объекты уже будут существовать.
3. В Authentication → URL Configuration добавьте `app.mira://auth` в разрешённые Redirect URLs. Для браузера добавьте точный адрес своего приложения (для локальной проверки — адрес с фиксированным портом).
4. Передайте URL проекта и публичный anon key при сборке. Это публичный ключ клиента; доступ к данным ограничен RLS. Service role и ключ AI нельзя передавать в приложение.

```bash
flutter run \
  --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
```

Для браузера можно зафиксировать порт:

```bash
flutter run -d chrome --web-port=8080 \
  --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
```

`SUPABASE_ANON_KEY` — legacy anon JWT из настроек API. Серверные функции проверяют access token через `auth.getUser`, а не доверяют данным запроса. `verify_jwt=false` в конфигурации функций не отключает проверку внутри кода.

Для CLI:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase db push
supabase functions deploy mira-ai
supabase functions deploy delete-account
```

## AI

Нужен доступ к API-провайдеру и выбранной модели с поддержкой Structured Outputs в Chat Completions. Название модели не зашито в код.

В Dashboard → Edge Functions → Secrets задайте:

- `OPENAI_API_KEY` — секретный ключ API;
- `OPENAI_MODEL` — доступный вашему аккаунту идентификатор модели;
- `ALLOWED_ORIGINS` — разрешённые browser origins, разделённые запятыми, например `http://localhost:8080,https://your-domain.example`.

Supabase автоматически предоставляет `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` функциям. Service role используется только на сервере для ограничения AI-запросов и удаления аккаунта. Не добавляйте секреты в Git.

Нативные приложения не передают Origin. Браузерные запросы с Origin вне списка отклоняются. Ограничение AI — 20 запросов на пользователя в час, включая неуспешные обращения к провайдеру. Фотографии не передаются AI. Содержание запросов и ответов не логируется кодом функции; условия хранения данных у провайдера нужно проверить отдельно.

AI не может удалять данные, покупать товары или произвольно вызывать API. При недостатке данных ответ может содержать только текст. Перенос событий пока предлагается текстом: приложение не исполняет его автоматически.

## Сохранение и синхронизация

`mira_documents` хранит один версионированный JSON-документ на пользователя. Это осознанная архитектура первой версии: проще обеспечить согласованность связанных модулей и хранение без интернета. Отдельные записи имеют ID, ссылки между ними не копируют сущности.

Запись в облако доступна только через `save_mira_document`. RPC проверяет пользователя, размер, версию схемы и ожидаемую ревизию. Новая версия другого устройства не перезаписывается молча. При конфликте пользователь выбирает облачную или локальную версию; автоматического слияния пока нет.

Размер документа ограничен 1 МБ. Для большого объёма данных следующей версии потребуются отдельные таблицы и построчная синхронизация. UI-данные локально хранятся в SharedPreferences без прикладного шифрования; токены сессии использует стандартное хранилище SDK Supabase. Это нужно учесть при требованиях к защите устройства.

Гость и аккаунты изолированы друг от друга. Переход в другой аккаунт не переносит данные автоматически. В профиле есть явный перенос гостевых данных с предупреждением о замене аккаунтной версии. Локальные гостевые фотографии при переносе загружаются в приватный bucket; для переноса нужен интернет.

Калории и БЖУ вводятся пользователем с упаковки. Рецепт рассчитывается из граммовок и количества порций. История приёмов пищи сохраняет снимок БЖУ даже при удалении исходного продукта/рецепта. Планы питания сохраняют снимок на момент планирования. Запасы продуктов не списываются автоматически: состав и единицы измерения запаса могут не совпадать с рецептом.

Цена носки считается по отмеченным запланированным образам, в которых есть вещь. Один отмеченный образ за дату считается одной ноской. При отметке носки сохраняется снимок ID вещей. Изменение состава или удаление образа не меняет прежние носки; при удалении образа отменяются только неотмеченные планы.

## Платформы и интеграции

- iOS: Xcode и CocoaPods на macOS; минимальная версия 13.0. Добавлены privacy descriptions для камеры, галереи и календаря, схема ссылки для Auth и делегат уведомлений.
- Android: JDK 17, Android SDK, minSdk 23. Добавлены INTERNET, уведомления, восстановление расписания после перезагрузки и desugaring. Напоминания неточные, ОС может задержать доставку. Exact Alarm permission не запрашивается.
- При выключении уведомлений или выходе из аккаунта запланированные уведомления пересоздаются для активного профиля.
- Камера и системный календарь проверяются на настоящих устройствах. Web не поддерживает календарь и локальные уведомления этой реализации; аккаунтные фото и основные разделы доступны.
- Экспорт календаря открывает системное окно добавления события. Импорт и двусторонняя синхронизация календаря пока не реализованы.
- Погода — текущие данные Open-Meteo по выбранному пользователем городу; геолокация не запрашивается. Нужен интернет. Для коммерческого релиза проверьте лицензию/условия Open-Meteo и выберите соответствующий тариф или провайдера.
- Дизайн использует цвета README, системные шрифты, светлую/тёмную тему и safe area. Лицензированные брендовые шрифты и финальные иконки для магазинов пока не добавлены.

## Проверки

Фактические результаты этой реализации: [VALIDATION.md](VALIDATION.md).

```bash
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
flutter build web --release --no-tree-shake-icons
flutter build apk --debug
# Только на macOS:
flutter build ios --simulator --debug
```

Backend:

```bash
deno check supabase/functions/mira-ai/index.ts supabase/functions/delete-account/index.ts
deno test supabase/functions/mira-ai/schema_test.ts
# Нужен Docker:
supabase start
supabase test db
supabase stop --no-backup
```

CI в `.github/workflows/ci.yml` запускает анализ, тесты, web/Android/iOS-сборки, проверку функций и SQL-тесты доступа. Отсутствие настроенных production-сервисов не мешает локальным тестам, но не подтверждает реальную работу интеграций.

Перед релизом выполните ручные сценарии из `docs/QA.md`. Эта версия не настроена для публикации: Android release использует debug signing из Flutter-шаблона; iOS-сертификаты не добавлены. Замените идентификатор `app.mira.mira`, иконки и подпись перед публикацией.
